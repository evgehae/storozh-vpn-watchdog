# Сторож VPN (WARP Watchdog)

Magisk-модуль для Android (root): следит за Cloudflare WARP (приложение 1.1.1.1) и автоматически чинит зависания туннеля, без ручного вмешательства.

## Зачем это нужно

WARP периодически зависает сам по себе: соединение формально есть, а трафик не идёт. Без модуля это выглядело так — сайт не грузится, нужно лезть в шторку, тыкать плитку вручную, иногда не с первого раза, иногда ждать, иногда помогала только полная очистка данных приложения. Сторож следит за этим в фоне и чинит сам, до того как успеешь заметить, что что-то сломалось.

Версия: **v4**. См. также [CHANGELOG.md](CHANGELOG.md).

## Что модуль делает в двух словах

Раз в 10–30 секунд проверяет, действительно ли WARP проксирует трафик (не просто «VPN подключён», а именно `warp=on`). Если нет — лечит лестницей: от лёгких мер к тяжёлым, с паузами между попытками, не чаще определённого лимита, без бесконечного долбления.

## Установка

1. Скачать zip, установить через Magisk → Модули → Установить из файла.
2. Перезагрузить устройство — обязательно, без этого часть настроек (Always-on VPN) не применится.
3. Один раз вручную открыть 1.1.1.1 и подключить WARP — модуль не настраивает VPN с нуля, только следит за уже настроенным.

## Как модуль проверяет, что всё в порядке

Три независимых проверки через `curl`, таймаут 6 секунд каждая:

| Проверка | Что делает | Зачем |
|---|---|---|
| `p_ip` | Запрос напрямую на `1.1.1.1` по IP, без DNS | Проверяет связность на уровне IP |
| `p_cf` (главная) | `https://www.cloudflare.com/cdn-cgi/trace`, смотрит `warp=on/off` | Отличает «VPN подключён» от «WARP реально проксирует» |
| `p_g` | `gstatic.com/generate_204` (как у самого Android) | Запасная проверка, если `p_cf` не прошла |

Сбой засчитывается только после **двух** неудачных проверок подряд (~10–20 сек) — одиночные случайные зависания игнорируются.

## После перезагрузки телефона: ждёт разблокировки

Пока телефон не разблокирован первый раз после перезагрузки, данные приложения WARP физически недоступны никому, включая root (шифрование хранилища) — WARP не может подключиться в принципе, что бы ни делал сторож. Модуль это обнаруживает и **не тратит попытки впустую**: просто тихо ждёт разблокировки, не запуская лестницу и не накапливая паузу между попытками. Как только разблокируете — сразу, без задержки, проверяет WARP с чистого листа.

## Лестница восстановления

Срабатывает по нарастающей, каждая ступень — только если предыдущая не помогла:

1. **Сброс DNS-кэша и Private DNS** — только если причина явно DNS.
2. **Полный перезапуск WARP** (`force-stop` + плитка) — основная рабочая ступень.
3. **Перезапуск Wi-Fi/мобильных данных** — выключено по умолчанию (`ALLOW_NET_BOUNCE=0`).
4. **Режим полёта** — выключено по умолчанию (`ALLOW_AIRPLANE=0`).
5. **Запасной VPN**, если настроен (`FALLBACK_PKG`) — по умолчанию выключено.

Перед тем как тронуть плитку, модуль **сначала тихо ждёт** (`SILENT_WAIT_SEC=25`), не поднимется ли WARP сам через Always-on VPN — без единого кадра UI. Плитка/шторка — только резерв, если тихое ожидание не сработало.

**Ограничения, чтобы не навредить:**
- Не больше `MAX_VPN_RESTARTS=3` принудительных перезапусков WARP за 10 минут.
- Общий потолок на всю лестницу: `MAX_RECOVERY_TIME=240` сек.
- После неудачи — пауза с нарастанием: 5 → 10 → 20 → 30 минут.
- Во время телефонного звонка — ничего не трогает.
- Если активен **другой** VPN (не WARP) — не вмешивается вообще.

## Смена сети (Wi-Fi ↔ мобильная)

Модуль отслеживает смену сети, но не реагирует на дребезг (секундное мелькание ID сети без реальной смены). После подтверждённой смены — ждёт (55 сек, если появился Wi-Fi; 40 сек в остальных случаях), затем проверяет: если WARP и так в порядке — ничего не делает. Если нет связности вообще (сеть ещё не готова) — не винит WARP, просто проверяет ещё раз через 10 сек, до 4 попыток.

Если сеть **нестабильна** (3 и больше смен подряд за 5 минут — например, слабый Wi-Fi-сигнал, из-за которого телефон мечется между Wi-Fi и мобильной сетью) — модуль это распознаёт и перестаёт активно перепривязываться на каждое отдельное дрожание, чтобы не устраивать бесполезную карусель перезапусков. В этом случае реальный сбой, если он останется, всё равно подхватит обычная лестница.

## Кнопка Action (в Magisk)

Пауза **и** выбор управляемого VPN:
- Нажали — пауза включена, модуль ничего не делает (даже если лестница уже идёт — прервётся).
- Пока пауза включена — вручную подключите любой другой VPN-клиент (не WARP).
- Нажали Action ещё раз — пауза снята, и сторож запоминает **тот VPN, который сейчас подключён**, как управляемый. Если в этот момент ничего не подключено — управляемый не меняется, остаётся прежним.
- Чтобы вернуться на WARP — та же процедура: пауза → вручную включить WARP → снять паузу.

### Чем WARP отличается от любого другого VPN в этом модуле

| Возможность | WARP (1.1.1.1) | Любой другой VPN |
|---|---|---|
| Проверка «подключён ли VPN» | ✅ | ✅ |
| Проверка «есть ли вообще интернет» | ✅ | ✅ |
| Проверка `warp=on/off` | ✅ точная | ❌ недоступна |
| Перезапуск через плитку / `force-stop` | ✅ | ✅ (если есть плитка) |
| Always-on VPN | ✅ | ✅ |
| Лестница восстановления | ✅ полная | ✅ полная, кроме `warp_broken` |

## Устойчивость самого процесса

Фоновый процесс сторожа защищён от собственного зависания на нескольких уровнях:
- Все системные вызовы (`dumpsys`, `am force-stop`, `settings`, `cmd statusbar`, `svc`, `ndc`) ограничены тайм-аутом.
- Сетевые проверки (`curl`, `ping`) защищены дважды — собственным внутренним тайм-аутом и внешним `timeout` поверх, на случай если первый не сработает при полностью сломанном сетевом стеке.
- Самоистекающая защита от выгрузки процесса системой (с таймаутом, не вечная) — если процесс всё же умрёт, блокировка сама снимется, не разряжая телефон впустую.
- «Пульс» в логе каждые ~20 минут — если процесс в следующий раз замолчит, виден последний момент, когда он точно был жив.

## Диагностика и команды

```sh
su -c 'sh /data/adb/modules/warp_watchdog/watchdog.sh status'
su -c 'sh /data/adb/modules/warp_watchdog/watchdog.sh check'
su -c 'sh /data/adb/modules/warp_watchdog/watchdog.sh diag'
su -c 'tail -n 60 /data/adb/warp_observer.log'
su -c 'tail -n 40 /data/adb/warp_diag.log'
```

## Конфиг: `/data/adb/warp_watchdog.conf`

Правится вручную, **требует перезагрузки** после изменения. Основные параметры: `ALLOW_DNS_BOUNCE`, `ALLOW_NET_BOUNCE`, `ALLOW_AIRPLANE`, `SILENT_WAIT_SEC`, `INTERVAL`, `MAX_VPN_RESTARTS`, `MAX_RECOVERY_TIME`, `FALLBACK_PKG`.

## Известные ограничения

- Иногда WARP зависает так, что его не поднимает вообще ничего (от минут до пары часов) — лечится полной очисткой данных приложения 1.1.1.1 (Настройки → Приложения → 1.1.1.1 → Хранилище → Очистить данные).
- Точная проверка `warp=on/off` работает только для самого WARP.
- На некоторых прошивках Always-on VPN может не применяться даже под root.
