# Сторож VPN (WARP Watchdog)

Magisk-модуль для Android: следит за Cloudflare WARP (приложение 1.1.1.1) и автоматически чинит зависания, без ручного вмешательства. Текущая версия: v1.6.14.

[Полный журнал изменений](CHANGELOG.md)

# Сторож VPN (WARP Watchdog) — гайд по работе и функционалу



## Что модуль делает в двух словах

Раз в 10–30 секунд проверяет, действительно ли WARP проксирует трафик (не просто «VPN подключён», а именно `warp=on`). Если нет — лечит лестницей: от лёгких мер к тяжёлым, с паузами между попытками, не чаще определённого лимита, без бесконечного долбления.

## Установка

1. Скачать zip, установить через Magisk → Модули → Установить из файла.
2. Перезагрузить устройство — обязательно, без этого часть настроек (Always-on VPN) не применится.
3. Один раз вручную открыть 1.1.1.1 и подключить WARP — модуль не настраивает VPN с нуля, только следит за уже настроенным.

## Как модуль проверяет, что всё в порядке

Три независимых проверки через `curl`, таймаут 6 секунд каждая:

| Проверка | Что делает | Зачем |
|---|---|---|
| `p_ip` | Запрос напрямую на `1.1.1.1` по IP, без DNS | Проверяет связность на уровне IP |
| `p_cf` (главная) | `https://www.cloudflare.com/cdn-cgi/trace`, смотрит `warp=on/off` | Отличает «VPN подключён» от «WARP реально проксирует» |
| `p_g` | `gstatic.com/generate_204` (как у самого Android) | Запасная проверка, если `p_cf` не прошла |

Сбой засчитывается только после **двух** неудачных проверок подряд (~10–20 сек) — одиночные случайные зависания игнорируются.

## Лестница восстановления

Срабатывает по нарастающей, каждая ступень — только если предыдущая не помогла:

1. **Сброс DNS-кэша и Private DNS** — только если причина явно DNS.
2. **Полный перезапуск WARP** (`force-stop` + плитка) — основная рабочая ступень.
3. **Перезапуск Wi-Fi/мобильных данных** — выключено по умолчанию (`ALLOW_NET_BOUNCE=0`).
4. **Режим полёта** — выключено по умолчанию (`ALLOW_AIRPLANE=0`).
5. **Запасной VPN**, если настроен (`FALLBACK_PKG`) — по умолчанию выключено.

Перед тем как тронуть плитку, модуль **сначала тихо ждёт** (`SILENT_WAIT_SEC=25`), не поднимется ли WARP сам через Always-on VPN — без единого кадра UI. Плитка/шторка — только резерв, если тихое ожидание не сработало.

**Ограничения, чтобы не навредить:**
- Не больше `MAX_VPN_RESTARTS=3` принудительных перезапусков WARP за 10 минут.
- Общий потолок на всю лестницу: `MAX_RECOVERY_TIME=240` сек.
- После неудачи — пауза с нарастанием: 5 → 10 → 20 → 30 минут.
- Во время телефонного звонка — ничего не трогает.
- Если активен **другой** VPN (не WARP) — не вмешивается вообще.

## Смена сети (Wi-Fi ↔ мобильная)

Модуль отслеживает смену сети, но не реагирует на дребезг (секундное мелькание ID сети без реальной смены). После подтверждённой смены — ждёт (55 сек, если появился Wi-Fi; 40 сек в остальных случаях), затем проверяет: если WARP и так в порядке — ничего не делает. Если нет связности вообще (сеть ещё не готова) — не винит WARP, просто проверяет ещё раз через 10 сек, до 4 попыток.

## Кнопка Action (в Magisk)

Пауза **и** выбор управляемого VPN:
- Нажали — пауза включена, модуль ничего не делает (даже если лестница уже идёт — прервётся).
- Пока пауза включена — вручную подключите любой другой VPN-клиент (не WARP).
- Нажали Action ещё раз — пауза снята, и сторож запоминает **тот VPN, который сейчас подключён**, как управляемый. Если в этот момент ничего не подключено — управляемый не меняется, остаётся прежний.
- Чтобы вернуться на WARP — та же процедура: пауза → вручную включить WARP → снять паузу.

### Чем WARP отличается от любого другого VPN в этом модуле

Переключить можно на любой VPN с своей плиткой в быстрых настройках, но не весь функционал одинаково хорошо работает с «чужим» VPN:

| Возможность | WARP (1.1.1.1) | Любой другой VPN |
|---|---|---|
| Проверка «подключён ли VPN» | ✅ | ✅ |
| Проверка «есть ли вообще интернет» | ✅ | ✅ |
| Проверка `warp=on/off` (отличить «подключён» от «реально проксирует») | ✅ точная | ❌ недоступна — у других VPN нет аналога `cdn-cgi/trace` |
| Перезапуск через плитку / `force-stop` | ✅ | ✅ (если у приложения есть плитка в быстрых настройках) |
| Always-on VPN (тихое восстановление без UI) | ✅ | ✅ (системная функция Android, не зависит от конкретного VPN) |
| Лестница восстановления | ✅ полная | ✅ полная, но ступень `warp_broken` никогда не сработает — такой диагноз ставится только для WARP |

**Главное ограничение:** без `warp=on/off` сторож для чужого VPN умеет отличать только «есть интернет» от «интернета нет». Та самая ситуация «VPN показывает Подключено, но трафик реально не идёт через тоннель» — которую мы специально научились ловить для WARP — для другого VPN останется незамеченной, если при этом какой-то интернет всё равно просачивается в обход. Если такой VPN вообще рвёт соединение при сбое (большинство так и делают) — разницы не будет, сторож всё равно поймает отсутствие интернета и полечит как обычно.

**Итог:** для WARP работает максимально точно, для любого другого VPN — чуть грубее, но ядро (слежение, лестница, Always-on, лимиты) работает одинаково для обоих.

## Диагностика и команды

```sh
# Текущий статус одной командой
su -c 'sh /data/adb/modules/warp_watchdog/watchdog.sh status'

# Разовая проверка без ожидания сбоя
su -c 'sh /data/adb/modules/warp_watchdog/watchdog.sh check'

# Прогнать одну ступень лестницы вручную
su -c 'sh /data/adb/modules/warp_watchdog/watchdog.sh step 2'

# Основной лог
su -c 'tail -n 60 /data/adb/warp_observer.log'

# Диагностика сети в момент сбоя (DNS-сервера, trace, физическая сеть)
su -c 'tail -n 40 /data/adb/warp_diag.log'
```

## Как читать лог

| Строка | Значение |
|---|---|
| `ip=on cf=on g=-` | Всё в порядке, WARP проксирует |
| `ip=on cf=off(6.00s)` | Единичное зависание DNS/WARP, пока не повод для тревоги |
| `СБОЙ (hard, причина: dns/tunnel/warp_broken)` | Подтверждённый сбой, запущена лестница |
| `warp_broken` | Особый случай: VPN подключён, но сам WARP не проксирует (`warp=off` в trace) |
| `... поднялся сам после force-stop (Always-on), без плитки` | Лучший исход — починилось без показа UI |
| `Резерв: разворачиваю шторку и жму плитку` | Тихое восстановление не сработало, резервный способ |
| `Смена сети: ... Ускоренная проверка 3 мин` | Обнаружена смена Wi-Fi/мобильной сети |
| `После смены сети WARP в порядке — не трогаю` | Хороший исход — не стал чинить работающий VPN |
| `Превышен общий лимит лестницы` | Не успели уложиться в 240 сек, прервано принудительно |
| `Следующая попытка через N мин` | Сработал бэкофф после неудачи |

## Конфиг: `/data/adb/warp_watchdog.conf`

Правится вручную, **требует перезагрузки** после изменения.

| Параметр | По умолчанию | Что меняет |
|---|---|---|
| `ALLOW_DNS_BOUNCE` | 1 | Ступень 1 (сброс DNS) |
| `ALLOW_NET_BOUNCE` | 0 | Ступень 3 (перезапуск сети) |
| `ALLOW_AIRPLANE` | 0 | Ступень 4 (авиарежим) |
| `PROACTIVE_REBIND` | 1 | Проверять WARP после смены сети |
| `REBIND_DELAY_SEC` / `_WIFI_SEC` | 40 / 55 | Задержка перед проверкой после смены сети |
| `SILENT_WAIT_SEC` | 25 | Сколько тихо ждать Always-on перед плиткой |
| `ALLOW_TILE_UI` | 1 | 0 = никогда не трогать плитку/шторку |
| `ALLOW_ALWAYS_ON` | 1 | 0 = не выставлять Always-on VPN самостоятельно |
| `INTERVAL` | 30 | Пауза между проверками, когда всё в порядке |
| `MAX_VPN_RESTARTS` / `_WINDOW` | 3 / 600 | Лимит перезапусков WARP |
| `MAX_RECOVERY_TIME` | 240 | Потолок на всю лестницу |
| `FALLBACK_PKG` | пусто | Запасной VPN (ступень 5), выключено по умолчанию |

## Известные ограничения

- **Иногда WARP зависает так, что его не поднимает вообще ничего** (бывало на 10 минут – 2,5 часа). Это не лечится сторожем — помогает **полная очистка данных приложения 1.1.1.1** (Настройки → Приложения → 1.1.1.1 → Хранилище → Очистить данные) и заново настроить WARP. Если это происходит чаще раза в сутки — стоит почистить заранее, не дожидаясь долгого провала.
- Умная проверка `warp=on/off` работает только для самого WARP — для другого VPN в `FALLBACK_PKG` сторож вернётся к более простой логике «есть интернет / нет интернета».
- На некоторых прошивках Always-on VPN может не применяться даже под root — тогда резерв (плитка/шторка) остаётся единственным рабочим способом.

## Если что-то пошло не так

1. Проверить статус: `watchdog.sh status`.
2. Посмотреть последние 60 строк `warp_observer.log` — ищите `СБОЙ`, `Превышен лимит`, повторяющиеся паттерны.
3. Если WARP не поднимается вообще ничем дольше 10-15 минут подряд — не ждать, сразу чистить данные приложения.
4. Если ставили сторонние iptables-модули (прокси, обход блокировок) — при похожих симптомах сначала удалить их и перезагрузиться, прежде чем разбираться дальше.
